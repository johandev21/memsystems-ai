# Domain documentation

This repository uses a single-context domain-documentation layout.

## Before exploring

- Read the root `CONTEXT.md` when it exists.
- Read relevant architecture decisions under `docs/adr/` when that directory exists.
- If either location is absent, proceed without creating placeholder documents.

## Vocabulary

Use the glossary vocabulary from `CONTEXT.md` in issue titles, specifications, implementation plans, tests, and code. Avoid introducing synonyms for established concepts. Record a genuine terminology gap through the domain-modeling workflow rather than silently inventing competing language.

## Architecture decisions

Surface any conflict with an existing ADR explicitly. Do not silently override an accepted decision.
